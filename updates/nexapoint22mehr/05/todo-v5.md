## قالب گزارش Agent (الزامی — همه پرامپت‌ها)

گزارش پایان **فقط لیست URL نیست**. Agent باید طبق **استاندارد تست E2E (داده فیک)** (همین فایل، بخش پایین) برای **هر صفحه/تب در scope همان مرحله** قابلیت‌ها را با **داده فیک** تست کند (محلی `npm run dev` یا بعد از deploy شما روی `nexapoint.ir` — هر کدام در آن لحظه ممکن است) و نتیجه را در گزارش بیاورد.

```text
## گزارش مرحله منو N
### کد و دیتا
- کارهای انجام‌شده: …
- migration جدید: بله/خیر — دستور VPS: …
- تیک‌های todo-v5 (P…): …
- باز مانده (کد): …

### محدوده تست (URL + منو)
- لیست مسیرها و تب‌ها (نه فقط لینک خام — برای هر مسیر یک خط «چه قابلیت‌هایی باید تست شود»)
- محیط تست: local | staging | nexapoint.ir · کسب‌وکار: … · کاربر: …

### ماتریس تست E2E (داده فیک)
برای هر ردیف: قابلیت | داده فیک (پیشوند FAUX-M{مرحله}-…) | عمل | انتظار | F5/ریلیشن | **اسکرین‌شات** (مسیر فایل) | نتیجه [x]/[ ] + علت

(حداقل همه ردیف‌های چک‌لیست مرحله در همین فایل + موارد اضافه اگر UI دارد)

### اسکرین‌شات‌ها (الزامی در تست)
- برای **هر صفحه/تب/URL** که تست می‌کنید حداقل **۱ اسکرین‌شات** بعد از بارگذاری (و در صورت فرم/ذخیره، یکی **قبل** و یکی **بعد** از submit/F5).
- مسیر پیشنهادی در repo: `updates/03/screenshots/M{N}/` — نام فایل: `M1-boards-after-save.png` (مرحله + محل + مرحله سناریو).
- در گزارش، مسیر هر عکس را در ستون اسکرین‌شات ماتریس بنویسید.
- **بازبینی از روی اسکرین‌شات:** بعد از پایان پیمایش، هر عکس را بازبینی کنید (متن، شمارنده، خطا، داده فیک در لیست) و اگر با تعامل زنده مغایرت بود هر دو را در گزارش ذکر کنید؛ PASS فقط وقتی که **زنده + اسکرین‌شات** با انتظار هم‌خوان باشند.
```

## استاندارد تست E2E (داده فیک)

| قانون | توضیح |
|--------|--------|
| **عمق** | هر صفحه: دکمه‌ها و فرم‌های اصلی، نه فقط «صفحه باز شد». |
| **داده فیک** | پیشوند `FAUX-M{شماره‌منو}-` + تاریخ (مثلاً `FAUX-M1-BOARD-2026-10-21`). از `COPILOT-UAT-2026-10-20` دوباره submit نکن مگر کاربر بخواهد. |
| **ذخیره** | بعد از create/update: لیست/جزئیات همان صفحه + **F5** + در صورت لزوم بازگشت از منوی دیگر. |
| **ریلیشن** | اگر موجودیت A به B وصل است (کارت→ستون، یادداشت→بورد، رویداد→تقویم، پروژه→عضو، نامه→گیرنده): هر دو طرف را در UI یا API چک کن. |
| **خطا** | ذخیره ناموفق باید پیام واضح داشته باشد؛ ۵xx/۴۰۳ را در گزارش ذکر کن. |
| **ابزار Agent** | ترجیح: browser MCP روی محیط در دسترس؛ در غیر این صورت تست API + `npm run test:*` مرتبط و در گزارش «UAT مرورگر: نشد — دلیل» بنویس. |
| **اسکرین‌شات** | هر URL/تب تست‌شده → `browser_take_screenshot` (یا معادل)؛ ذخیره در `updates/03/screenshots/M{N}/`؛ ماتریس + **مرور مجدد عکس‌ها** برای تأیید نتیجه. |
| **مرجع مرحله ۱** | جزئیات سناریو: [`updates/03/copilot-phase-01-quick-access.md`](updates/03/copilot-phase-01-quick-access.md) + **چک‌لیست قابلیت‌ها — مرحله ۱** در همین فایل. |

# توضیحات و جزئیات (بعد از پرامپت‌ها)

## چطور با این فایل کار کنم؟

1. پرامپت شمارهٔ **مرحلهٔ باز** را از بالا کپی → Agent mode.
2. Agent **فقط کد** (و migrate محلی / اسکریپت backfill) — **نه** push، **نه** deploy روی VPS.
3. **گزارش پایان** را Agent خودش می‌دهد (شامل **ماتریس تست E2E** با داده فیک، نه فقط URL) → شما **push + deploy** → دستورات VPS از گزارش.
4. روی `https://nexapoint.ir` **همان ماتریس** را تأیید کنید؛ برای **هر صفحه** اسکرین‌شات بگیرید و در `updates/03/screenshots/M{N}/` ذخیره کنید؛ نتیجه را از روی عکس‌ها هم بازبینی کنید.
5. در **جدول اول صفحه** تیک «کد» / «deploy» / «تست فرانت» بزنید → در **تیک مرحلهٔ کامل** همان مرحله را `[x]` کنید → عنوان **مرحله N** در بخش پرامپت را به `[x]` تغییر دهید → پرامپت بعدی.
