## موارد باز و تأییدنشده

### زیرساخت، استقرار و عملیات

این اجرا دسترسی SSH، کنسول Runflare، فایل env سرور، دیتابیس production یا پیکربندی webhook نداشت؛ بنابراین موارد زیر **باز/تأییدنشده** هستند:

- رفع migration ناموفق، `migrate resolve`, migration additive یا `db push`/baseline.
- اجرای `db:seed-settings` یا `db:seed-safe-places`.
- `db:promote-admin` و تطبیق نقش ادمین از API.
- وجود/صحت متغیرهای `BALE_*`, `TABANSMS_EMERGENCY_*`, `UPLOAD_ROOT`, `MAX_UPLOAD_BYTES`, `PUBLIC_FILES_BASE_URL` و `GEMINI_API_KEY`.
- نصب/تأیید webhook بله.
- پاسخ `GET /api/auth/me` و `role=admin`.
- اثبات اینکه آخرین commit مدنظر deploy شده است.

از آنجا که GET بدون کوکی به `/admin` redirect شد، محافظت route در همین لحظه تأیید شد؛ اما این موضوع به‌تنهایی نقش کاربر، auth API یا موفقیت deploy اخیر را اثبات نمی‌کند.

### End-to-end و نوشتن داده

این سناریوها عمدی **SKIPPED** ماندند یا API آن‌ها مستقیماً بررسی نشد:

- ارسال SMS یا Bale، هشدار آزمایشی به یک/همهٔ مخاطبین، SOS و اقدام‌های فوری رسانه‌ای/موقعیت.
- دریافت `/start` از webhook بله، ثبت chat ID واقعی، و پخش فایل رسانه‌ای.
- ثبت پروژهٔ آزمایشی و تأیید `POST /api/freelance/projects` در Network.
- پیشنهاد وکیل، wallet و درخواست تسویه.
- تغییر favorite و تأیید endpoint آن.
- ذخیره تنظیمات امنیتی و تأیید `PATCH /api/user/security-settings`.
- تغییر/ذخیره تنظیمات ادمین و مشاهدهٔ اثر در فوتر/سایت.
- CRUD واقعی بلاگ.
- تأیید ثبت‌نام وکیل از جریان OTP واقعی.
- تأیید `GET /api/admin/stats` و `/api/admin/analytics` با status 200 و تطبیق KPI/نمودار با دادهٔ DB.
- `GET /api/emergency/events`, `/how-it-works`, AI با/بدون کلید و پیام graceful.
- تست نهایی U4 در Incognito و تأیید نبود flash پس از آخرین deploy.

فرستادن SOS/هشدار یا ثبت/تغییر داده روی production بدون مخاطب آزمایشی و تأیید صریح انجام نشد. seed نیز روی production اجرا نشد.

## هشدارهای UI برای اصلاح/بازآزمایی

1. امتیاز مکان امن در `/home` به رقم لاتین نمایش داده می‌شود.
2. در `/home` وضعیت «مخاطب تعریف نشده» موقتاً پیش از تکمیل دریافت داده ظاهر می‌شود.
3. `/profile` گاهی برای چند ثانیه در loading می‌ماند؛ علت Console 403 در این اجرا مشخص نشد.
4. فرم افزودن مخاطب روی موبایل محتوای بلند و اسکرول داخلی دارد؛ در انتهای اسکرول دکمه‌ها قابل دسترسی‌اند، اما دوباره روی دستگاه واقعی تأیید شود.
5. اندازهٔ مؤثر مرورگر گاهی به‌جای عرض درخواستی ۳۷۵ به ۳۱۲ پیکسل تغییر کرد. نتایج و تصاویر اندازهٔ واقعی را در گزارش UI ثبت کرده‌اند؛ قبل از بستن U4 در Chrome DevTools واقعی تکرار شود.
6. نمودارهای ادمین در تصویر کم‌وضوح/عمدتاً خالی به نظر می‌رسند؛ این QA منشأ داده یا خطای endpoint را تعیین نکرد.
